# Участие в разработке

Спасибо за помощь в улучшении `postfix-relay-rescue`.

[English version](CONTRIBUTING.md)

## Перед созданием issue

- Используйте последний релиз.
- Прочитайте README и существующие issues.
- Удалите пароли, содержимое частных писем, чувствительные публичные IP и
  данные, позволяющие определить клиента.
- Укажите версию ОС, почтового стека или Mail-in-a-Box и Postfix, точную
  команду, ожидаемый результат и очищенный вывод.

Уязвимости сообщаются по [SECURITY.ru.md](SECURITY.ru.md), а не через публичный
issue.

## Pull Request

1. Сделайте fork и создайте отдельную ветку под конкретное изменение.
2. Не объединяйте в одном PR несвязанные изменения.
3. Добавьте или обновите моковые тесты для изменённого поведения.
4. Обновите английскую и русскую документацию при изменении интерфейса.
5. Выполните:

   ```bash
   bash -n postfix-relay-rescue.sh tests/run-smoke.sh tests/mock-bin/prr-mock
   shellcheck -x postfix-relay-rescue.sh tests/run-smoke.sh tests/mock-bin/prr-mock
   bash tests/run-smoke.sh
   ```

6. Опишите влияние на безопасность Postfix и механизм отката.

## Стиль Bash

- Только Bash; сохраняйте `set -Eeuo pipefail`.
- Заключайте expansions в кавычки, кроме документированных случаев splitting.
- Для генерации конфигурации используйте `printf`, а не `echo`.
- Никогда не передавайте пароли аргументами или переменными окружения.
- Любое изменение Postfix должно быть транзакционным.
- Сохраняйте посторонние записи в map-файлах и настройки администратора.
- Перед reload обязательно выполняйте `postfix check`.
- Не используйте `restart`, если достаточно безопасного `reload`.

## Правила тестирования

Тесты не должны затрагивать реальные:

- `/etc/postfix`;
- сервис Postfix;
- DNS-настройки;
- почтовую очередь;
- пользовательские ящики.

Используйте моки из `tests/mock-bin/` и временные пути через переменные
окружения `PRR_*`.

## Коммиты и релизы

Используйте понятные commit subject в повелительной форме. Пользовательские
изменения добавляйте в `CHANGELOG.md` и `CHANGELOG.ru.md`.

Отправляя вклад, вы соглашаетесь на его публикацию по лицензии MIT.
