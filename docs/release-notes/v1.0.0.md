# postfix-relay-rescue v1.0.0

The first public release turns a real Postfix/Spamhaus DBL failure mode into a
repeatable and reversible recovery workflow. Mail-in-a-Box is the primary
tested platform.

## Highlights

- Configure any hostname-based authenticated STARTTLS relay.
- Detect and reuse an existing Postfix `relayhost`.
- Preserve the host's global SMTP TLS policy and require TLS only for the relay.
- Detect the Postfix configuration directory and common mail-log paths.
- Refuse an ambiguous global bypass when `master.cf` overrides sender
  restrictions for an individual service.
- Stop sender-RHSBL from rejecting authenticated local users.
- Preserve sender-login anti-spoofing and external inbound DBL filtering.
- Audit SPF, DBL, ZEN, maps, duplicate parameters, and the mail queue.
- Rotate relay credentials without deleting unrelated map entries.
- Create complete snapshots and automatically roll back failed changes.
- Send and trace a real test message to the next SMTP hop.
- Watch DBL state changes from cron.
- Validate behavior through isolated mocked smoke tests.

## Important

An SMTP relay changes the connecting IP. It does not remove a sender domain
from Spamhaus DBL. Use the official Spamhaus Reputation Checker for removal.

`status=sent` confirms acceptance by the next SMTP hop, not final inbox
placement.

See [README.md](../../README.md) for installation and usage.

## Русский перевод

Первый публичный релиз превращает реальную проблему Postfix и Spamhaus DBL в
повторяемый и обратимый сценарий восстановления. Основная протестированная
платформа — Mail-in-a-Box.

### Основное

- Подключение любого авторизованного STARTTLS-релея по hostname.
- Определение и переиспользование уже настроенного Postfix `relayhost`.
- Сохранение глобальной TLS-политики сервера и обязательный TLS только для
  релея.
- Определение каталога Postfix и стандартных путей почтовых логов.
- Отказ от неоднозначного глобального bypass, если `master.cf` переопределяет
  sender restrictions для отдельного сервиса.
- Защита локальных авторизованных пользователей от блокировки sender-RHSBL.
- Сохранение anti-spoofing и входящей DBL-фильтрации.
- Аудит SPF, DBL, ZEN, map-файлов, дублирующихся параметров и очереди.
- Ротация пароля без удаления посторонних записей.
- Полные снимки и автоматический rollback неудачных изменений.
- Отправка и трассировка реального теста до следующего SMTP-узла.
- Наблюдение за DBL через cron.
- Изолированные моковые smoke-тесты.

### Важно

SMTP-релей изменяет подключающийся IP, но не удаляет домен отправителя из
Spamhaus DBL. Для удаления используйте официальный Spamhaus Reputation
Checker.

`status=sent` подтверждает приём следующим SMTP-узлом, а не попадание письма во
«Входящие».

Установка и использование описаны в [README.ru.md](../../README.ru.md).
